# Diagnostyka CH340 i uprawnień

## Sprawdzenie adaptera

```bash
lsusb | grep 1a86                 # oczekiwane: 1a86:7523 QinHeng CH340
lsmod | grep ch341                # sterownik jądra
dmesg | tail -20                  # "ch341-uart converter now attached to ttyUSB0"
ls -l /dev/ttyUSB0 /dev/serial/by-id/
```

Stabilna ścieżka `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0` jest widoczna w zakładce Połączenie i może być wpisana jako domyślny port (nie zmienia się po ponownym podłączeniu).

## Uprawnienia (`dialout`)

```bash
id -nG | tr ' ' '\n' | grep dialout || sudo usermod -aG dialout "$USER"   # potem wyloguj się
```

Aplikacja nie wymaga root ani sudo. Błąd „Permission denied” (Errno 13) jest rozpoznawany w Diagnostyce.

## Port zajęty

```bash
fuser -v /dev/ttyUSB0
systemctl status ModemManager     # potrafi przejmować porty USB-UART
```

Zamknij proces lub poproś ModemManager o ignorowanie adaptera (reguła udev - tylko jeśli faktycznie to konieczne).

## Brak odpowiedzi MCU („Waiting for MCU…”)

1. CH340 jest wykryty, ale to nie dowodzi obecności MCU.
2. Połączenia: TX adaptera → RXD (P3.0) MCU, RX adaptera → TXD (P3.1), wspólna **GND**.
3. Poziomy logiczne: STC8H pracuje na 3,3 V lub 5 V - adapter musi odpowiadać napięciu zasilania układu (aplikacja go nie przełącza).
4. Po kliknięciu „Wykryj mikrokontroler” **wyłącz i włącz zasilanie MCU** (sama linia DTR zwykle nie zasila układu).
5. Spróbuj protokołu `stc8d`, niższego handshake (1200/2400) i krótszych przewodów.
